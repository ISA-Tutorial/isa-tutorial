Activity C: Grounded Live-Corpus

A hands-on Jupyter notebook that demonstrates why some questions can only be answered by searching the live open web — and how to do that reliably using SearXNG, a free open-source metasearch engine that requires no API key or account.

Notebook link coming soon · Colab T4 GPU or laptop CPU · ~20 min

How to run this notebook

Option A — Google Colab (easier)

  1. Click the button above once the link is live (check back before the tutorial).
  2. In the top-left menu choose File → Open in Colab.
    Use a personal Google account rather than a work or university account — institutional accounts sometimes block third-party Colab access.
  3. Make it editable: File → Save a copy in Drive.
    The shared notebook is view-only; saving a copy to your own Drive gives you a personal, fully editable version.
  4. Enable a free GPU: Runtime → Change runtime type → T4 GPU → Save.
    A GPU is not required (the default model runs on CPU) but speeds up generation.
  5. Run cells top-to-bottom with Runtime → Run all, or step through them with Shift+Enter.

Option B — Local Jupyter (laptop)

  1. Download the notebook from the Drive link (File → Download → Download .ipynb).
  2. Install dependencies: pip install transformers torch requests
  3. Open with jupyter notebook activity_c.ipynb or in VS Code / Cursor.
  4. The default model (Qwen2-0.5B-Instruct) and SearXNG both work without GPU or API keys.

What you will learn

  • Why LLMs alone, structured APIs, and fixed-corpus RAG all fail for questions that require today's information.
  • How to use SearXNG as a free, keyless metasearch engine that aggregates 240+ search providers simultaneously.
  • How to build a grounded live-search prompt that instructs the LLM to cite source URLs and publication dates.
  • How to handle heterogeneous source quality and conflicting snippets from the open web.
  • What evaluation looks like at Level 4: freshness, source credibility, and answer faithfulness — all three required.

Complexity Ladder level covered

LevelNameKey property
4 Grounded Live-Corpus Open web retrieval for freshness. One-shot search → multi-source synthesis → cited answer. Evaluation requires freshness check, source credibility check, and answer faithfulness check.

Notebook outline

  • Setup: install 3 packages (transformers, torch, requests); load Qwen2-0.5B-Instruct (CPU-friendly default; swap to Phi-3.5-mini on T4).
  • Part 1 — LLM alone fails: ask a "this week" AI policy question with no context → stale/hedged answer; explain training cutoff.
  • Part 2 — SearXNG live search: searxng_search() helper with automatic instance fallback → inject top results as context → LLM gives current cited answer → repeat for 3 diverse live questions.
  • Part 3 — Comparison: same live question fails on a hardcoded static corpus; decision table for when to use Level 2 vs. 3 vs. 4.
  • Part 4 — Source quality: inspect which search engines contributed each result; handle a deliberately ambiguous query where sources disagree.
  • Part 5 — Recap: full Complexity Ladder table comparing Levels 2–5; Level 4 → 5 transition explained.

Requirements

No API keys or signups needed:

  • Live search: SearXNG public instances — free, no account, aggregates 240+ search engines. The notebook automatically tries several instances in order.
  • Self-host option: run your own SearXNG with docker run -d -p 8080:8080 searxng/searxng and point the notebook to http://localhost:8080 for a private, unthrottled instance.
  • Default model: Qwen/Qwen2-0.5B-Instruct — 0.5 B params, ~1 GB, runs on CPU.
  • GPU upgrade (optional): microsoft/Phi-3.5-mini-instruct — swap in the first code cell when running on Colab T4.
